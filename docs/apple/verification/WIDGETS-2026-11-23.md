# Native widget rebuild — 2026-11-23

This change uses Xcode, SwiftUI and WidgetKit in `apple/`. It does not change the Electron floating widget in the 0.5 desktop installer. The native apps have separate bundle IDs; existing Electron data can be transferred with a calendar backup after native signing is configured.

## Behavior

- `FRIWidgetContent` is shared by both WidgetKit extensions and the app's size preview. It measures the available space with `ViewThatFits`, trying full agenda, summary, next task plus date, then the essential task content. Large text falls back to a vertical arrangement. Titles have bounded lines, preserve the full accessibility label, and use limited font scaling. The completion control retains a 44-point target.
- Small, medium, large and extra-large WidgetKit families are supported where the OS offers them. The host owns the outside frame and content margins; there is no nested fixed-size window or custom resize grip. Empty days do not show an unusable Done button.
- The Add FRI Widget sheet previews small/medium/large with example or current-day data and a large-text option. The preview is explicitly labeled and does not modify appointments. Xcode timeline previews additionally cover extra-large, empty and locked states.
- Move and resize use the platform widget host: drag on the Mac desktop; long-press and edit the Home Screen on iOS. The app explains the platform/version-specific steps. FRI does not programmatically install or move widgets.
- Timeline projection prioritizes active appointments, then upcoming appointments, then unfinished past appointments. Timelines include both start and end boundaries, deduplicate times and cap at 31 entries. The provider asks for a new timeline after the last planned boundary (or local midnight), with a 15-minute retry for unavailable storage.
- AppIntent completion remains idempotent and uses the protected shared store. Data marked privacy-sensitive stays marked in the shared rendering.

Signed Mac widget-gallery registration, App Group/Keychain access, completion from an actual installed widget, physical iPhone placement, successful drag relocation, lock/reboot and device upgrade are not established by unsigned builds or an in-app preview. Configure the owning team's identifiers in the ignored `apple/Config/Local.xcconfig`, sign both host and extension, then verify these journeys. Do not replace the installed Electron app with the unsigned native Release app and call it a working release.

## Reproduce

```sh
swift test --package-path apple/Packages/FRICore
xcodebuild build -project apple/FRI.xcodeproj -scheme FRIMac \
  -configuration Release -destination 'generic/platform=macOS' \
  -derivedDataPath apple/DerivedData/widget-release-mac \
  ARCHS='arm64 x86_64' CODE_SIGNING_ALLOWED=NO
xcodebuild build -project apple/FRI.xcodeproj -scheme FRIiOS \
  -configuration Release -destination 'generic/platform=iOS' \
  -derivedDataPath apple/DerivedData/widget-release-ios CODE_SIGNING_ALLOWED=NO
xcodebuild test -project apple/FRI.xcodeproj -scheme FRIiOS \
  -configuration Debug -destination 'platform=iOS Simulator,id=SIMULATOR_UDID' \
  -derivedDataPath apple/DerivedData/widget-ios -parallel-testing-enabled NO \
  -only-testing:FRIiOSUITests/FRIWorkflowTests/testWidgetAutoFitAtEverySize \
  CODE_SIGNING_ALLOWED=NO
```
